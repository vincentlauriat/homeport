Homeport

A home server dashboard that reads what your machine already knows — and presents it well.

Four readings of the same truth
Services, honestly

It shows you the disagreement, not a green tick.

Each service combines Docker state, systemd state and a live probe. When they disagree — a container that runs but no longer answers — Homeport calls it degraded and opens the card on the reason. That is exactly what docker ps hides.

What it watches

Everything the machine already knows.

The machine

CPU, memory, temperatures, SSD wear, power incidents, journal errors, pending updates, backup freshness — with 7 days of history and Internet outages overlaid.

A one-year logbook

The events that matter, on a day-grouped timeline: services falling and recovering, Internet outages, new devices, admin actions, boots and power incidents — with container logs one click away.

The network around it

LAN inventory with real names (yours → mDNS → vendor), new-device detection, Tailscale peers, latency and outage tracking, Wake-on-LAN.

The link to the outside

Optional modules read your Starlink dish or your operator box directly, on the local network — obstruction, throughput, WAN state, and the outages they cause.

Nothing to babysit

One Python service, one SQLite file, one YAML config re-read on every request. No agents, no external database, no JavaScript framework.

Yours, in your language

English and French — each browser picks its own language from the footer, and its own theme: light, dark, or follow the system.

Designed for a home, secured like one

The LAN is strictly read-only.

Actions require a Tailscale-verified identity, and restarts go through exact-command sudo rules — never through the Docker socket, which Homeport only reaches read-only via a proxy. Outbound traffic is two optional calls, public IP and update check, both disablable. No telemetry.
